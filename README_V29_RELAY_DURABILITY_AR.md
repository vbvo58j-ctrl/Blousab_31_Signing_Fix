# نسخة 29 — متانة صندوق الرسائل والترحيل

## التغييرات

1. إضافة `RelayQueueStore.enqueueIfNew` لتسجيل حزمة الترحيل ومعرّفها ضمن عملية متسلسلة واحدة. تُحفظ الحزمة أولاً ثم يُحدّث سجل المعرفات المرئية؛ إذا امتلأت القائمة أو فشل التخزين فلا يُحجز المعرّف، وبذلك يمكن إعادة المحاولة لاحقاً.
2. تغيير استقبال الحزم في `chat_screen.dart` لاستخدام `enqueueIfNew` بدلاً من تسجيل `markSeen` قبل حفظ الحزمة. هذا يعالج حالة فقد الحزمة نهائياً إذا امتلأت قائمة الترحيل بعد تسجيلها كمشاهدة.
3. جعل قراءة مخزن الترحيل وصندوق الرسائل المعلقة تفشل بوضوح عند تلف JSON بدلاً من إرجاع قائمة فارغة ثم الكتابة فوق البيانات القديمة.
4. إضافة كتابة عبر ملف مؤقت ثم إعادة تسمية لحفظ قوائم الترحيل وصندوق الإرسال، لتقليل احتمال تلف الملف عند انقطاع التطبيق أثناء الكتابة.

## حدود هذه الدفعة

- هذه التغييرات تحسن موثوقية التخزين المحلي ولا تضيف تشفيراً أو مصادقة تشفيرية للحزم.
- LAN وWi-Fi Aware ما زالا يحتاجان مصادقة نظير وتشفيراً طرفياً موثقاً.
- لا يزال اختبار Android/Flutter والبناء الفعلي واختبار هاتفين/ثلاثة هواتف مطلوباً.
- لا تعتمد على هذه النسخة لتبادل بيانات حساسة قبل إغلاق موانع الأمان وإجراء مراجعة مستقلة.
